# Швидкі опитування

## Сценарій ведучого

1. У пульті знайдіть «Швидкі опитування» та натисніть «Створити».
2. Введіть запитання до 200 символів і рівно 2 або 4 різні непорожні відповіді до 100 символів кожна.
3. Збережіть питання. Картка має дії «Редагувати», «Копія», «Видалити» та «Запустити · 10 с».
4. Під час показу натисніть плаваючу кнопку «Опитування» внизу праворуч, виберіть збережене питання та натисніть «Запустити». Віджет працює також у повноекранному режимі, його можна згорнути й перетягнути за заголовок.
5. Запуск показує екран голосування замість слайда на ноутбуці й телефонах. Завантажений PDF не є обов’язковим.
6. Через 10 секунд результати автоматично замінюють питання: кількість голосів і відсоток кожної відповіді. Без голосів показуються нулі.
7. «До слайдів» на екрані результатів або «Повернутися до слайдів» у віджеті закриває результати. Питання можна запустити знову з новим ідентифікатором раунду та порожніми результатами.

Віджет використовує ту саму бібліотеку питань, що й редактор. Збереження, редагування, копіювання та видалення одразу оновлюють список швидкого запуску. «Створити / редагувати питання» повертає до редактора; за потреби виходить із повноекранного режиму.

Віджет існує лише в пульті ведучого: телефони не отримують його інтерфейс або список ще не запущених питань. Це не захист від зовнішнього захоплення екрана: якщо транслювати весь робочий стіл або вікно пульта через іншу програму, віджет теж буде видно. Для такого сценарію показуйте окреме вікно учасника, відкрите через посилання приєднання, а пульт залишайте на своєму екрані.

## Якщо замість запуску виникає помилка JSON

Після зміни серверного коду одного оновлення браузера недостатньо. Старий Node.js-процес може віддавати новий інтерфейс із диска, але не знати нових API-маршрутів: тоді повертається HTML `404`, що раніше показувався як `Unexpected token '<'`. Пульт тепер виявляє старий стан сервера й показує зрозумілу інструкцію замість помилки парсера.

Зупиніть сервер, повторіть `npm start` і відкрийте нове повне посилання з термінала. PDF потрібно завантажити знову, а телефони приєднати через новий QR. Збережені питання залишаються в тому самому браузері за тією самою адресою й портом. Не очищуйте дані браузера для виправлення цієї помилки.

Під час відкритого голосування новий раунд запустити не можна. «Скасувати опитування» просить підтвердження й повертає до показу без результатів. Навігація слайдами та малювання в пульті тимчасово вимкнені, доки екран питання або результатів відкритий. Після закриття зберігається особиста позиція перегляду учасника.

Редагування збереженого питання не змінює запущений раунд: сервер отримує окрему копію запитання й відповідей. Це опитування думок, не тест із правильною відповіддю; балів, рейтингу та акаунтів немає.

## Збереження

Бібліотека містить до 50 питань у `localStorage` під ключем `slidesync-polls-v1`. Вона належить браузеру й HTTP-джерелу ноутбука: зміна адреси, порту, профілю або очищення даних браузера змінює доступ до неї. При заблокованому сховищі інтерфейс попереджає, що питання залишаються лише в поточній вкладці. Між пристроями бібліотека не синхронізується.

Поточний раунд і голоси існують лише в пам’яті сервера. Перезапуск сервера прибирає їх і створює нову сесію. Експорт результатів і перенесення бібліотеки не входять у цей обсяг.

## Стан і дедлайн

Поле `poll` повного стану дорівнює `null` або містить:

```json
{
  "id": "унікальний-id-раунду",
  "question": "Що обговоримо далі?",
  "options": ["Приклади", "Практика"],
  "status": "open",
  "startsAt": 1000,
  "endsAt": 11000,
  "total": 1,
  "vote": 0,
  "counts": null
}
```

Сервер завжди встановлює `endsAt = startsAt + 10000`. Клієнт не задає тривалість. Таймер сервера переводить раунд у `results` і транслює новий стан; додаткові перевірки при читанні та голосуванні не дозволяють прийняти прострочений голос навіть при затримці таймера. У стані `results` поле `counts` містить масив лічильників у порядку відповідей; до дедлайну воно завжди `null`, зокрема для ведучого.

`vote` — лише власний індекс відповіді цього учасника або `null`. Сервер персоналізує HTTP-відповіді, WebSocket-знімки й heartbeat. Він не надсилає учасникам таблицю чужих голосів. Браузер показує відлік через `serverTime` і локальний монотонний годинник, але результат отримує тільки від сервера. При розриві мережі нуль на таймері не вигадує результати.

## HTTP API

| Маршрут | Доступ | JSON |
| --- | --- | --- |
| POST `/api/host/polls/start` | Loopback + `X-Host-Token` | `{question, options}` |
| POST `/api/host/polls/cancel` | Loopback + `X-Host-Token` | `{pollId}` |
| POST `/api/polls/vote?token=…` | Ключ учасника + cookie його браузера | `{pollId, answer}` |

Успішні запити повертають повний стан; незмінний повтор власного голосу є ідемпотентним. Заміна вже прийнятої відповіді, прострочений голос або старий `pollId` дають `409`; неправильний індекс чи питання — `400`. JSON обмежений 4 КіБ. Максимум 10000 прийнятих голосів у раунді — межа пам’яті, не обіцянка підтримки такої кількості телефонів у Wi-Fi.

## Ідентичність і мережеві межі

Авторизований HTTP-запит видає випадковий ідентифікатор браузера у cookie з HMAC-підписом, `HttpOnly` і `SameSite=Strict`. Повторне завантаження, reconnect і кілька вкладок одного браузерного профілю зберігають один голос. Підписана cookie не містить ключа ведучого й не дозволяє довільно підмінити інший відомий ідентифікатор.

Це не перевірка фізичної людини: інший профіль/браузер, приватне вікно або очищення cookie можуть дати новий голос. Cookie мають бути дозволені. WebSocket учасника вимагає попередньо видану підписану cookie: звичайний клієнт спочатку отримує HTTP-знімок і лише потім підключає сокет. Без cookie залишаються HTTP-перегляд і пояснення помилки голосування. Без TLS cookie й голоси не захищені від перехоплення в недовіреній мережі; використовуйте лише довірену LAN.

HTTP fallback підтримує питання, голосування та результати. Через крок опитування 3 секунди показ нового питання або результатів може запізнитися, але серверний дедлайн не подовжується. Повернення Safari з фону бере актуальний стан і власний голос. Фізичні iPhone/Android та місткість конкретної мережі потребують ручного тестування.

## Перевірки

```sh
npm test
npm run test:browser -- test/browser/polls.spec.mjs
```

- Модульні: 2/4 відповіді, межі тексту, дублікати, незмінні копії, дедлайн 9999/10000 мс, ідемпотентність, старі раунди, нуль голосів, таймери й межа пам’яті.
- Серверні: авторизація, HMAC-cookie, персоналізований WebSocket/reconnect, відсутність передчасного розподілу голосів, автоматичний результат через реальні 10 секунд.
- Браузерні Chromium/WebKit: CRUD і збереження бібліотеки, голосування двома профілями, перезавантаження, HTTP fallback, автоматичні результати, повернення до PDF, робота без PDF й скасування.

Ручний чеклист: перевірте 2 і 4 відповіді на реальних телефонах, портрет/альбом, повноекранний пульт, повернення з фону після дедлайну, дуже довгі питання, нуль голосів, обрив Wi-Fi та повторний запуск питання. Переконайтеся, що підсумки не видно до завершення голосування.
