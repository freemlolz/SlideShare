# Технічне завдання: MVP SlideSync Local

Версія: 0.1.0. Оновлено: 30 жовтня 2026 року.

## Мета і користувачі

Ведучий запускає застосунок на ноутбуці, завантажує PDF і керує показом. Учасники приєднуються з iPhone/Android через QR та бачать поточний слайд у браузері. Інтернет і встановлення застосунку на телефони не потрібні. Усі операції виконуються локально; використання платних API або хмарної інфраструктури заборонене.

## Обсяг MVP

Одна сесія та одна активна PDF-презентація на процес сервера. Один пульт на ноутбуці, довільні вкладки перегляду в межах пропускної здатності LAN. Підтримка актуальних Safari/Chrome; тестова автоматизація Chromium і WebKit. Фізичні iPhone та Android проходять окремий ручний тест.

Поза обсягом: Bluetooth, PPTX/Keynote, трансляція робочого столу, відео й звук, учасницькі акаунти, хмара, мобільний застосунок, remote control з телефона, особисті малюнки учасників, голосування, багатокімнатність, HTTPS і збереження сесій між запусками.

## UI та стани

Пульт: стан з’єднання, екран слайда, лічильник сторінок, кнопки навігації, завантаження PDF, QR, список IPv4, копіювання посилання, кількість учасників, повна готовність кешів, коротка мережева допомога.

Переглядач: слайд зі збереженням пропорцій, номер, прогрес кешування, з’єднання, кнопка розгортання, попередній/наступний і повернення до поточного кадру. Ручна навігація переводить лише цю вкладку в перегляд історії. Наступний доступний до найбільшого номера, отриманого вкладкою від ведучого в поточній презентації; це правило інтерфейсу, а не захист уже завантажених JPEG. Альбомний і портретний режими не обрізають слайд. Стани: немає ключа, очікування PDF, завантаження, показ, історія, reconnect, fallback, помилка сесії. Помилки не повинні руйнувати наявний кадр.

Пульт містить панель малювання, доступну також у повноекранному режимі. Малюнки вирівнюються за зображенням PDF, а не за чорними полями навколо нього. На історичному кадрі не показується шар поточного слайда. Після заміни PDF або перезавантаження вкладки учасник повертається до автоматичного слідування.

Інтерфейс українською. Поля мають label, кнопки навігації — доступні назви, помилки — `role=alert`, статуси — `role=status`. Клавіші не перехоплюються під час введення в полях і взаємодії з кнопками.

## HTTP API

| Метод і маршрут | Авторизація | Призначення |
| --- | --- | --- |
| GET `/host` | мережевий loopback | HTML пульта; без ключа API недоступний |
| GET `/join` | публічна оболонка | HTML перегляду; без ключа контент недоступний |
| GET `/assets/*` | публічні статичні ресурси | JS/CSS/HTML оболонки, без секретів |
| GET `/api/host/config` | loopback + `X-Host-Token` | `{links:[{address,url,qr}],limits}` |
| POST `/api/host/pdf` | loopback + `X-Host-Token` | `multipart/form-data`, одне поле `pdf`; відповідь — повний стан |
| POST `/api/host/slide` | loopback + `X-Host-Token` | JSON `{deckId,index}`; відповідь — повний стан |
| POST `/api/host/annotations` | loopback + `X-Host-Token` | JSON дії малювання; відповідь — повний стан |
| GET `/api/state` | ключ перегляду `?token=` або loopback + `X-Host-Token` | повний актуальний стан |
| GET `/slides/:deckId/:page.jpg` | аналогічно стану | JPEG; номер сторінки від 1; `private, immutable` кеш |
| UPGRADE `/ws?role=viewer&token=…` | ключ перегляду | стан і звіти готовності |
| UPGRADE `/ws?role=host&token=…` | loopback + ключ ведучого | стан для пульта |

Некоректна авторизація перегляду: `401`; керування/джерело: `403`; неіснуючий слайд: `404`; зайнята конвертація або застарілий deckId: `409`; завеликий PDF: `413`; непридатний PDF/пароль/таймаут: `422`. Некоректний індекс/формат запиту: `400`. API повертає JSON `{error:"повідомлення"}`. Помилки віддачі файла чи невідомий маршрут можуть бути стандартною HTTP-відповіддю.

## WebSocket-протокол

Сервер надсилає об’єкт `state`, описаний в архітектурі. Індекс слайда від нуля, версія монотонна в межах `sessionId`. Повідомлення до 2048 байт від клієнта. Стиснення WebSocket вимкнене.

Учасник може надсилати:

```json
{"type":"ready","deckId":"поточний-id","loaded":5}
```

Сервер перевіряє поточний deckId та цілий loaded від 0 до кількості сторінок. Це телеметрія готовності, а не доказ, що користувач фізично бачить кадр. Команди перемикання через учасницький сокет ігноруються. Пошкоджений JSON дає повідомлення `error`, не зупиняє процес.

## Протокол малювання

HTTP-команда містить `deckId`, `index`, `epoch` і `action`. Дія `clear` очищає шар та збільшує epoch. Для `append` потрібні `id`, `points` і `finished`; при створенні лінії також `tool` (`pencil`, `brush`, `marker`), `size` (1–32), `color` (`#RRGGBB`), `lifetime` (0 або 5000 мс). Точка — `[x,y,pressure]`, усі числа скінченні й нормалізовані до 0–1. Інтерфейс пропонує розміри 3, 6, 12 і 20.

Пакет має до 32 точок і вкладається у чинний ліміт JSON 2 КіБ. Між пакетами зберігається порядок; при завершенні дозволений порожній пакет для вже початої лінії. Шар обмежений 64 лініями, 6000 точками загалом і 1500 точками на одну лінію. Зайвий обсяг відхиляється без часткової зміни стану. Незавершена лінія прибирається через 30 секунд без нових пакетів.

Невідповідність deckId/index/epoch дає `409`, некоректні дані — `400`, перевищення обсягу — `413`. Запізнілі пакети не можуть відновити очищений малюнок, навіть якщо ведучий повернувся на той самий слайд. Постійні лінії зберігаються лише в пам’яті сервера до очищення, зміни слайда/PDF або зупинки.

## Нефункціональні вимоги

Робота PDF поза головним потоком, щоб активний показ не блокувався. Послідовне створення JPEG стримує накопичення полотен. На клієнті — не більше двох фонових запитів та окремий запит актуального кадру. Продуктивність залежить від PDF, ноутбука, якості Wi-Fi та кількості одночасних завантажень.

Орієнтир для ручної перевірки: перемикання вже кешованого слайда на двох активних телефонах у домашній LAN зазвичай вкладається в 0,5 секунди. Це ціль для польового тесту, не гарантія MVP і не результат лабораторного вимірювання. HTTP fallback має крок опитування 3 секунди; timeout і нестабільна мережа можуть збільшити затримку.

Не використовувати глобальне вимкнення захисту Safari, брандмауера чи модифікацію системних налаштувань як умову штатного сценарію. Документація має пояснити прямий HTTP-доступ, одноадресний WS, firewall, ізоляцію клієнтів, VPN та повернення з фону.

## Приймання та завершення

MVP приймається після проходження інтеграційних і браузерних тестів, ручного показу PDF на фізичному iPhone/Safari та Android/Chrome у цільовій LAN, перевірки без інтернету й відновлення після блокування екрана. Автоматизація WebKit не замінює реальний iPhone. Відомі неперевірені пункти мають бути вказані в протоколі тестування.

Поставка: вихідні файли, зафіксовані залежності, демонстраційний генератор PDF, автоматичні тести, архітектура, це технічне завдання, інструкція запуску та ручний чеклист. Інсталяційний `.dmg`/`.exe` не входить у MVP: це локальний застосунок, який запускається через Node.js.
