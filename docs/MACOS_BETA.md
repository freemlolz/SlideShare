# SlideSync Local — macOS Beta

## Для користувачів

Node.js, Terminal і встановлення на телефонах не потрібні. Потрібен Mac із macOS 14 або новішою та Wi-Fi-мережа без ізоляції пристроїв.

1. Завантажте DMG для свого Mac: `arm64` — Apple Silicon (M1 та новіші), `x64` — Intel. Тип процесора видно в меню Apple → «Про цей Mac».
2. Відкрийте DMG й перетягніть **SlideSync Local** до **Applications / Програми**.
3. Запустіть застосунок із «Програми». Локальний сервер запускається сам; адреси й ключі вручну вводити не потрібно.
4. Якщо macOS запитає, дозвольте застосунку доступ до локальної мережі та вхідні з’єднання. Це потрібно для телефонів у вашій Wi-Fi-мережі, не для хмари.
5. Натисніть «Вибрати файл», оберіть PDF, потім «Завантажити PDF». Телефони приєднуються через QR у Safari або Chrome.
6. Дочекайтеся попереднього завантаження слайдів. Після цього керуйте показом, малюйте й запускайте опитування як у браузерній версії.

Поки застосунок відкритий, він не дає Mac автоматично приспати екран і систему. Це не захист від закриття кришки, ручного сну або вимкнення живлення. Не закривайте кришку Mac під час показу.

Закриття вікна або `⌘Q` потребує підтвердження. Після завершення телефони від’єднуються, тимчасові PDF/JPEG та голоси видаляються. Новий запуск створює новий QR; PDF треба завантажити знову. Збережені питання залишаються в застосунку на цьому Mac, зокрема після зміни порту.

### Важливе обмеження бети

Це безкоштовна тестова збірка з локальним ad-hoc підписом, **без Apple Developer ID і нотаризації**. macOS може заблокувати її після завантаження з інтернету. Ad-hoc підпис не підтверджує особу розробника. Для довіреної збірки перевірте джерело й контрольну суму; за потреби скористайтеся штатною можливістю macOS «Системні параметри → Конфіденційність і безпека → Відкрити попри це». Остаточне рішення приймає користувач. Не вимикайте Gatekeeper і не запускайте команди для зняття захисту. Корпоративна політика може повністю забороняти такі збірки.

Плавне встановлення без попереджень потребує окремої підписаної й нотаризованої збірки; обліковий запис Apple Developer не входить до безкоштовної бети. App Store й автоматичних оновлень у цій версії немає. Оновлення встановлюють вручну, замінюючи застосунок у «Програми».

### Якщо телефон не приєднується

- Mac і телефон мають бути в одній доступній локальній мережі. Гостьовий Wi-Fi може блокувати зв’язок навіть за однакової назви мережі.
- Дозвольте SlideSync Local локальну мережу в параметрах macOS і вхідні з’єднання в брандмауері. Не вимикайте брандмауер цілком.
- За наявності VPN оберіть у QR-панелі адресу Wi-Fi, а не VPN.
- Використовуйте актуальний QR. Звичайна браузерна версія на порту 3000 і desktop-застосунок можуть працювати одночасно: desktop автоматично обере інший порт.
- Сервер працює лише доки працює застосунок. HTTP/WS не шифруються; використовуйте довірену LAN й не відкривайте порт в інтернет.

Ліміти ті самі: PDF до 40 МіБ / 150 сторінок, без пароля. PPTX, анімації та хмарний показ не підтримуються.

## Для розробників

```sh
npm ci
npm run desktop
npm test
npm run test:desktop
npm run test:browser
npm run desktop:dist -- --x64
npm run desktop:dist -- --arm64
```

`npm ci` потребує Node.js 22.13+; це вимога лише до розробника. Перше `npm run desktop` завантажує офіційний Electron. Збірка також потребує інтернету для інструментів, але встановлений застосунок працює без нього. Збірки створюються локально на macOS у `dist/`; `--publish never` забороняє автоматичну публікацію. DMG, згенеровані іконки, особисті PDF та ключі сесій не додаються в Git. Обирайте лише команду для архітектури свого Mac: `--x64` на Intel, `--arm64` на Apple Silicon з нативним arm64 Node. Hook `desktop/before-pack.cjs` відхиляє кросзбірку, щоб не випустити застосунок без потрібного нативного canvas. Apple Silicon DMG не вважається готовим, доки його окремо не зібрано й не перевірено на такому Mac.

`npm run desktop:pack` створює лише `.app` без DMG. Для перевірки саме запакованого застосунку:

```sh
SLIDESYNC_DESKTOP_EXECUTABLE="$PWD/dist/mac/SlideSync Local.app/Contents/MacOS/SlideSync Local" npm run test:desktop
```

Для arm64 каталог зазвичай `dist/mac-arm64`. Тест створює окремий тимчасовий профіль через `--user-data-dir`, завантажує демонстраційний PDF, перевіряє синхронізацію браузера, збереження питань, новий порт при конфлікті та очищення під час виходу. Він не змінює особисті опитування й не зупиняє інші сервери. Нативні arm64-збірки слід окремо запускати на Apple Silicon; Intel-перевірка не є такою перевіркою.

Перед розповсюдженням обчисліть контрольні суми й прикладіть DMG та цей документ до релізу вручну:

```sh
shasum -a 256 dist/*.dmg
```

### Внутрішня будова

- `desktop/main.mjs`: один екземпляр, вікно ведучого, сервер, захист від сну, підтвердження виходу й очищення.
- `desktop/runtime.mjs`: вибір вільного порту та вузький список дозволених переходів/посилань.
- `desktop/preload.cjs`: ізольований міст лише для читання й збереження питань; без довільного IPC, файлів чи команд.
- `desktop/store.mjs`: перевірка структури, максимум 50 питань, атомарна заміна `desktop-state.json` із правами `0600` у `~/Library/Application Support/SlideSync Local/`. Зберігає тільки порт і питання, не PDF, голоси чи ключі.
- `electron-builder.json`: macOS DMG, локальний підпис, жодних мережевих служб під час показу. `asar: false` залишає звичайні шляхи для PDF worker, локальних шрифтів/WASM і нативного canvas. Вихідний код не є секретним.
- `public/polls.js`: у desktop використовує вузький міст, у звичайному браузері — колишній `localStorage`. Банки питань браузера й desktop окремі; автоматичного перенесення немає.

Вікно має `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, звичайну перевірку веббезпеки та серверний CSP. Chromium-сесія тимчасова, дисковий HTTP-кеш вимкнений; JPEG не залишаються в постійному браузерному кеші після завершення показу. Нові вікна заборонені; тільки актуальне локальне посилання учасника можна відкрити в системному браузері. IPC перевіряє саме головний кадр поточного вікна й адресу `/host`. Керування сервером, як і раніше, потребує loopback та окремого токена. Телефони не отримують можливостей Electron.

Electron і пакувальник — залежності лише для розробки. Нативний `@napi-rs/canvas` використовує Node-API; збірка повинна включати його бінарник відповідної архітектури. Автоматичне переналаштування глобального Node або брандмауера не виконується.
