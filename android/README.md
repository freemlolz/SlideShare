# SlideSync Local — Android Beta

Android-телефон ведучого замінює ноутбук: обробляє PDF, запускає локальні HTTP/WebSocket-сервери й показує QR. Учасники відкривають слайди у Safari або Chrome, без встановлення застосунків. Хмари, платних API, облікових записів і зовнішніх запитів під час показу немає.

## Встановлення та показ

1. На Android 8.0 або новішому відкрийте `SlideSync-Local-Android-0.1.0-beta.1.apk` з довіреного джерела.
2. Android може попросити дозволити встановлення з конкретного браузера/файлового менеджера. Не вимикайте Play Protect. Корпоративна політика або системна перевірка розробника може забороняти сторонні APK.
3. Відкрийте **SlideSync Local**, натисніть **Вибрати PDF** й оберіть локальний файл. Для роботи без інтернету файл уже має бути на телефоні, а не лише в хмарному провайдері файлів.
4. Натисніть **Почати показ**. Дозвольте локальну мережу, якщо Android попросить; дозвіл на повідомлення допоможе бачити стан і кнопку завершення.
5. Дочекайтеся підготовки всіх сторінок. Оберіть адресу Wi-Fi, якщо є кілька інтерфейсів. Учасники в тій самій мережі сканують QR і чекають попереднього завантаження.
6. Кнопки **Назад / Далі** керують показом. На телефонах учасників можна переглядати попередні слайди й повернутися до поточного.
7. Завершуйте показ кнопкою в застосунку або повідомленні SlideSync. Новий показ створює нове посилання й QR.

Інтерфейс українською. Сторонні бібліотеки й ліцензії доступні кнопкою **Про застосунок і ліцензії**.

## Межі першої бети

- **PDF лише:** до 40 МіБ / 100 сторінок, без пароля. Сумарні JPEG — до 32 МіБ, найдовший бік до 1280 px. Це окремі мобільні ліміти; вони відрізняються від ноутбука.
- Малювання, опитування, бібліотека презентацій і детальна панель стану учасників ще не перенесені. Лічильники враховують WS-вкладки, не фізичні телефони; HTTP-резерв у них не врахований.
- Потрібна мережа, де пристрої можуть зв’язуватися. Ізоляція гостьового Wi-Fi й обмеження VPN залишаються. Власну точку доступу можна перевірити вручну, але її сумісність не гарантована й застосунок не вмикає її автоматично.
- HTTP/WS не шифруються. Використовуйте довірену LAN; не відкривайте порти в інтернет. QR дає доступ до всіх сторінок поточного PDF, а не тільки до вже показаних.
- Перед початком усі сторінки готуються на телефоні; великі або складні PDF можуть бути повільними. Використовуйте власні/довірені PDF й актуальні системні оновлення Android. У цій беті платформний `PdfRenderer` ще не винесений в окремий ізольований процес для ворожих документів.
- Показ підтримується foreground-сервісом із повідомленням. У відкритому пульті екран не засинає; частковий wake lock має межу 4 години. Економія батареї, ручна зупинка або обмеження виробника можуть перервати роботу. Для першого польового тесту залишайте пульт відкритим і майте зарядку.
- Поворот екрана та тимчасовий вихід з пульта не повинні завершувати показ. Видалення задачі з меню останніх застосунків завершує його. Автоматичного відновлення показу після вбивання процесу немає.
- Тимчасові копії зберігаються лише у приватному кеші. Нормальне завершення прибирає PDF/JPEG; залишки аварійного завершення прибираються при наступному створенні сервісу. Початковий вибраний файл не видаляється. Уже завантажені копії у браузерах учасників дистанційно не стираються.
- Це APK для прямого тестового встановлення, не реліз Google Play. Автоматичних оновлень немає.

## Будова

```text
android/
  app/src/main/
    AndroidManifest.xml
    java/io/github/freemlolz/slidesync/
      MainActivity.java             пульт, системний вибір PDF, QR
      PresentationService.java      foreground-життєвий цикл і очищення
      PdfDeck.java                  локальний PDF → JPEG
      PresentationServer.java       HTTP, стан, WebSocket
      BoundedWebSocketFactory.java  межі з’єднань і handshake
      NetworkAddresses.java         адреси Wi-Fi / інших інтерфейсів
    assets/                         сторонні ліцензії
  app/src/test/                     модульні перевірки меж з’єднань
  app/src/androidTest/              PDF, мережа й життєвий цикл на Android
  gradle/wrapper/                   Gradle wrapper
```

Gradle копіює лише потрібні файли переглядача з `../public` до згенерованих APK assets. HTML/JS пульта ноутбука та Node.js не включаються. Дубльованого ручного форка браузерного інтерфейсу немає.

Телефон слухає два вільні локальні порти: HTTP та WebSocket. Поле `websocketPort` у стані вказує браузеру другий порт; за відсутності поля ноутбучна версія й далі використовує свій колишній порт. HTTP fallback залишається на HTTP-порту.

HTTP і WS перевіряють актуальний випадковий ключ учасника та локальне джерело запиту. HTTP-керування ведучим відсутнє: навіть з ключем учасник не може перемикати слайди. Керує тільки внутрішній, неекспортований Android-сервіс. Обмеження: 64 WS-з’єднання включно з незавершеними handshake, handshake до 8 КіБ / 7 секунд, кадр WS до 4 КіБ; HTTP-пул — 16 активних запитів і 32 у черзі. Це захисні межі, не обіцянка стабільного показу на 64 телефонах. Реальну місткість Wi-Fi треба виміряти.

Дозволи: локальна мережа/мережевий стан, foreground-сервіс, wake lock і повідомлення. `CHANGE_NETWORK_STATE` оголошений як передумова типу foreground-сервісу `connectedDevice`; застосунок не змінює Wi-Fi. Камера, мікрофон, контакти й широкий доступ до сховища не потрібні. Файли обираються системним діалогом. Backup/перенесення приватних даних вимкнені. Аналітики немає.

## Збірка

Потрібні Android SDK 37, Build Tools 36.0.0 та JDK 17+ (перевірено з Android Studio JBR 25). Gradle wrapper — 9.6.0, Android Gradle Plugin — 9.4.1. Відкрийте папку `android` в Android Studio або використайте:

```sh
cd android
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest
```

Для підписаної релізної бети з кореня репозиторію:

```sh
npm run android:beta
```

Node.js потрібен лише для допоміжного сценарію збірки, не користувачам APK. Задайте `JAVA_HOME` та `ANDROID_HOME`; на macOS сценарій також знаходить стандартні шляхи Android Studio. Початкова збірка завантажує відкриті залежності. Runtime не потребує інтернету.

Сценарій створює приватний ключ у **`android/.signing/`**, виконує `assembleRelease`, модульні тести й `lintRelease`, потім копіює APK та SHA-256 до **`dist/android/`**. `dist`, build-каталоги, ключ і пароль виключені з Git.

**Збережіть приватну резервну копію всієї `android/.signing/`.** Для оновлення вже встановленої бети потрібен той самий ключ і більший `versionCode`. Не публікуйте ключ або `beta.properties`. Якщо один файл ключа відсутній, сценарій відмовляється непомітно міняти особу підписувача. Сертифікат самопідписаний: його наявність не означає перевірки розробника Google.

APK додають до GitHub Releases як окремий файл, не комітять у дерево вихідного коду. Автоматичної публікації цей сценарій не робить.

## Перевірки

На окремому тестовому емуляторі встановіть debug APK та APK з `app/build/outputs/apk/androidTest/debug`. Використовуйте конкретний серійний номер, не особистий телефон:

```sh
adb -s emulator-5580 install --no-streaming -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5580 install --no-streaming -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5580 shell am instrument -w -r io.github.freemlolz.slidesync.test/androidx.test.runner.AndroidJUnitRunner
```

З кореня репозиторію `npm run test:browser -- test/browser/android-transport.spec.mjs` перевіряє окремий WS-порт у Chromium/WebKit на локальному стенді. Для справжнього Android-бекенду є `scripts/test-android-browser.mjs`: він потребує вже зібраних і встановлених debug/test APK у disposable AVD **SlideSyncTest**, запускає тестовий foreground-показ і підключає Chromium/WebKit через локальний ADB forward. Тестові команди слайдів передаються приватним файлом під `run-as`, не мережевим API; harness існує тільки в окремому test APK.

```sh
ANDROID_SERIAL=emulator-5580 node scripts/test-android-browser.mjs
```

Польові перевірки перед ширшим релізом: фізичний Android 8/13/17, реальний iPhone/Safari, вимкнення/повернення Wi-Fi, блокування екрана й економія батареї різних виробників, 10+ телефонів, hotspot, довга презентація та встановлення APK з браузера на чистий телефон. Емулятор або WebKit-автоматизація не замінюють ці перевірки.
